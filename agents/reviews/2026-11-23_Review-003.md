## Review notes

- **Detection is exact for the pinned Ghostty.** `bt_uses_legacy_key_encoding` (`native/bridge/brows_ghostty.c:330-344`) rejects nonzero Kitty flags, then encodes a synthetic Shift+Tab. In Ghostty's Tab table, Shift+Tab is `CSI Z` only for `.modify_other_keys = .set` and `CSI 27;2;9~` for `.set_other` (`native/ghostty/src/input/function_keys.zig:187-193`). No other encoder option (cursor key, keypad, Num Lock keypad, or backarrow mode) affects the Tab entries. Records are chosen only when the result is exactly `CSI Z`, so an unexpected encoding or any Ghostty error falls back to Ghostty's encoding, the pre-change behavior.
- **Mode changes are followed without duplicate parsing.** The probe reads Ghostty's state, so `CSI > 4 m` (`native/ghostty/src/terminal/stream.zig:2316-2321`), `CSI > 4 ; 0/1 m`, and full reset (`native/ghostty/src/terminal/Terminal.zig:5954`) all restore records without bridge changes.
- **The probe is side-effect free.** It writes into a stack buffer and never calls `write_pty`. `prepare_key` sets every key event field that `bt_key` sets, so the shared `t->key` and `t->keys` state cannot leak into the next real key. A NULL UTF-8 pointer is accepted by Ghostty as empty text (`native/ghostty/src/terminal/c/key_event.zig:98-100`). The probe runs under `bt_lock` in `bt_session_win32_input`, the same recursive lock that serializes `bt_key`.
- **The test checks ordering, not just presence.** `ModifiedKeys_FollowModifyOtherKeysModeChangesInTheSameSession` expects `CSI 27;2;13~`, `CSI 27;5;13~`, `CSI 27;2;9~`, the marker, CR, and the second marker, in that order. KeyEcho writes `CSI > 4 m` before `key-echo-reset`, and the test waits for that text, so Ghostty has cleared mode 2 before the second Shift+Enter. The CR assertion also documents the remaining gap for VT readers that request neither protocol, which the README now states.

## Residual risks

- **A mode left on by an exited application keeps Ghostty's encoding.** If a VT application enables mode 2 or Kitty flags and then exits without clearing them, for example after a crash or forced termination, the terminal keeps the mode. A later classic console reader such as PSReadLine then receives Ghostty's sequences, and ConPTY drops Shift+Enter as it did before `9c3919c`. This is not a regression from the original baseline `cf69183`, and the same exposure already existed for Kitty flags in `9c3919c`. The bridge cannot observe which console client set the mode, so there is no proportionate fix in this scope.
